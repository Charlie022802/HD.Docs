Plan agreed 2026-07-22, build starts next session. Convert the WinForms `HD.Animal.Proxy.Controller` into a **Blazor Server** web app so colleagues configure the proxy via browser, deployed on the same Linux host (192.168.68.222) as the proxy services. Retires the WinForms Controller (web-only from now on). See [[project_hd_animal_proxy]] for the host/SELinux context it builds on.

New project: `HD.Animal.Proxy.WebController` (Blazor Server, net10, linux-x64), added to HD.Animal.slnx. References core lib `HD.Animal.Proxy` (ProxyConfig model) + fo-dicom 5.2.6 (C-ECHO). No SFTP (runs on the host → direct local file access, unlike the old WinForms StartForm SFTP model).

Decisions (from user):
1. User store = **SQLite** at `/var/lib/hdanimal/webcontroller.db`, passwords PBKDF2/Identity PasswordHasher (never plaintext). Seed super-admin **`hdadmin` / `hdadmin`** on first run (simple default, user changes it after first login), changeable in UI.
2. **HTTPS self-signed** cert (generated at install), Kestrel on port **8080**.
3. Port **8080**, open firewall.
4. Add PACS/Worklist AETitle/Port/Timeout editing (was in the deleted MainFormAdvance) — pairs with restart button since those need a service restart.
5. "Restart services" button — via **polkit rule** (`/etc/polkit-1/rules.d/49-hdanimalproxy.rules`) letting user hdadmin restart the hdanimalproxy* units, web calls `systemctl restart` directly (NOT sudo — sudo is SELinux-blocked for init_t). Fallback if polkit/SELinux fights: web writes a restart-request file that the root ServiceManager executes.
6. Retire WinForms Controller.

Auth: Cookie auth, two roles **Admin** / **User**. Only Admin sees `/users` (CRUD + password reset). Users see config + logs only.

Pages: `/login`, `/config` (RemoteAEList, UuidMapping, PACS/Worklist, ServiceManager incl HistoryRetentionDays, InputRules — tabbed; Save + Restart), `/logs` (pick service+date from /var/log/hdanimal, show, manual refresh, historical files), `/users` (Admin only).

Config read/write = atomic write of `/opt/hdanimal/proxyConfig.json` + `.bak`. **SELinux wrinkle**: /opt/hdanimal is usr_t (read-only for services); the web app must WRITE proxyConfig.json → relabel just that file to `var_lib_t` (services read it fine, web writes it). Also 8080 `name_bind` and polkit/systemctl restart may need additions to the existing `hdanimalproxy` SELinux policy module. SQLite db + cert under /var/lib/hdanimal (var_lib_t, writable). New systemd unit `hdanimalproxywebcontroller.service` (User=hdadmin). All baked into install.sh/uninstall.sh.

Build order: (1) skeleton + login/cookie/roles + SQLite users + seed hdadmin → (2) config page (AE/UUID/Rules/ServiceManager + save) → (3) log viewer → (4) user management (Admin) → (5) PACS/Worklist fields + restart button (polkit) → (6) deployment (cert/unit/firewall/SELinux/install.sh) + on-host verify.
