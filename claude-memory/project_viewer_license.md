**看片端授權機制(REQ-012,正本 `docs/viewer-license-design.md`)。✅ 2026-08-14 全部完成並端到端驗證通過。**

**最重要的一個轉折:從離線改成線上註冊。** 原設計是帶 `.req` 回原廠簽、再帶授權檔回現場;但痛點不在簽章,而是「**醫師的個人電腦我們連不到,拿檔案一定要跑現場**」。關鍵觀察:**看片端本來就要連醫院主機的 PostgreSQL 才能看片 ⇒ 能看片就一定連得到 DB**。於是拿 `HD_DEVICE_LICENSE` **當信箱**:看片端 INSERT 申請 → 我們 VPN 進 .191 主控台按簽發 → 授權字串寫回 `LICENSE_TEXT` → 看片端下次啟動自己取回落地。**不開埠、不加服務、不必在每間醫院部署主控台。** 討論時要點破的是:「傳輸怎麼走」與「誰拿私鑰」是**兩個獨立問題**——傳輸改了,私鑰仍只在原廠,因為寫回去的必須是原廠簽的字串,自己塞的驗不過(那張表只是郵筒不是核准權)。離線流程完整保留當備援,兩條路格式相同。

**⚠️ 目前 `LicenseGate.Enforce = false`(蒐集階段,不擋人)。** 現場既有看片端全是「從來不必註冊」的狀態,一上版就擋等於自己把所有醫院鎖住。流程:先出 `false` 的版本讓清冊自動長出來 → 把在用的機器全簽掉 → 下一版才改 `true`。刻意做成**編譯期常數不是設定檔開關**(設定檔裡放「把授權關掉」的開關比不做還糟)。**下次動工第一件事就是確認要不要翻這個旗標。**

**實作時發現的三個真問題(都是照原設計會出事的)**
1. **`Win32_Processor.ProcessorId` 是型號層級的值**(實測 `178BFBFF00B60F00`),同款 CPU 全都一樣 → 複製到**同型號**的另一台會中一項 → 原規則判成「漂移→放行」,而同型號正是醫院整批採購的常態。改列**弱識別**:只中它一項時當作不同機器(但若可比對的只有那一項,仍放行)。
2. **主控台 `IssuedAt`/`LastIssuedAt` 是非 nullable**,pending 列一進來 Dapper materialization 直接炸,**整頁打不開**;`ORDER BY LAST_ISSUED_AT DESC` 也會把 NULL 排最前面。(是使用者問「待簽發頁應該還沒上 .191 吧?」才想到我剛塞的 pending 列會弄壞線上的舊版。)
3. **換發判定原本看「這一列在不在」**,但線上申請已先佔一列,第一次簽發會被記成換發 → 改看 `ISSUE_COUNT > 0`。

**格式(`HD.Shared.Licensing`,簽發端與驗證端共用同一份)**:ES256;**簽的是 payload 原始位元組**(不是解析後重新序列化,否則 JSON 空白/順序有差就驗不過);加 `typ` 做**域分離**(舊授權檔沒有這欄視為 license,仍驗得過);**`chain` 憑證鏈驗證路徑已寫通但沒在用**——現在做幾乎免費,等授權都發出去才做的話所有既有看片端會全部驗不過。15 項機制測試。

**看片端判斷順序**:①本機 `%ProgramData%\HyperDigital\DicomImageViewer\license.lic` 驗簽+四取二(**不碰 DB**,實測 30ms)②DB 用 DeviceId(沒有才用指紋,且只認 Match)找自己那列,已簽發就抓回落地(**重灌/重裝/誤刪自動復原**)③沒有就 INSERT pending ④DB 不通走離線匯出/匯入。**任何一步失敗都只安靜退回下一條**(含 42P01 表不存在=舊環境沒跑 migration)。暫用 72 小時,線上以 **DB 的 `REQUESTED_AT`** 為準(記本機的話重灌就能刷新=無限試用)。撤銷靠**背景回報** `LAST_SEEN_AT`,發現時畫面已開起來,所以記本機、**下次啟動**才處理+7 天寬限(硬關正在判讀的視窗是臨床風險)。

**正式公鑰已內嵌** `LicenseTrust.RootPublicKeyBase64`(`MFkwEwYH...o9ds8Q==`),來源 `.191:/etc/hd-admin-console/license-signing.key`(**確認過 `hostname -I` 是 .191**,不是 .199)。主控台 `/licenses` 新增可展開的「本站台的簽發公鑰」,以後對「看片端內嵌的是不是這台簽的」不必再 ssh 下 openssl。DEBUG 組建才吃 exe 旁的 `license-public.pem`(Release 也吃的話,任何人放自己的公鑰就能自簽)。

**⚠️ 閘門掛在「登入成功之後」不是程式啟動時**(2026-08-14 使用者點破):資料庫位址是**登入畫面的齒輪**在設定的,全新安裝 `localconfig.json` 位址刻意留空 → 放在 Main 就等於「第一次啟動必然走連不上那條」,而且 `PostgresSettings` 預設 Host 是 `127.0.0.1`,會卡滿 10 秒逾時才出現登入畫面。改掛 `LoginForm.LogIn()` 裡帳號驗過+`RefreshConfigs()` 成功之後(Core 只留 `Func<IWin32Window,bool>` 掛鉤,機制在 exe 那層因為要 `System.Management`)。**代價是把 WMI+DB 擠到「按下登入」那一刻**——使用者最有感的位置,實測體感明顯變差 → 指紋改**啟動時背景預熱**(139ms 移出關鍵路徑)+「表不存在」記住不再問(253→41ms)。**副作用:關 VPN 測不到離線註冊**,因為登入本身要連 DB,登入先失敗就走不到閘門;離線那條真正的觸發條件是「DB 通但沒有授權表」。

**十項實測全過(2026-08-14,看片端指向 .163 當醫院、簽發在 .191)**,抓到六個只有實裝才現形的問題,全修掉:①蒐集階段仍跳註冊視窗(「已送出申請」是放行卻帶訊息)②按下登入變慢(見上)③**註冊視窗被登入視窗蓋住**——`LoginForm` 是 `TopMost`,給對話框擁有者不夠,要照程式裡既有前例(「啟動設定」按鈕)先 `TopMost=false` 再 `finally` 還原;順便改 `CenterParent`(多螢幕)④「重新檢查」同步跑在 UI 執行緒→凍住像沒反應,改背景+「檢查中…」+「最後檢查」時間⑤主控台產 `.dat` 但看片端只認 `.lic`(統一 `.lic`,主控台 alpha.4)⑥「沒有裝置授權表」只寫結論不寫原因,測試中真的遇到表消失卻查不下去 → 帶 SqlState+原始訊息+連到哪個 DB/帳號。

**順手修掉的既有 bug(不是這次改出來的)**:連不到主機時跳「使用者[XXX]登入錯誤」——連線失敗與密碼錯在上層都只是 `Success=false`,現場會照著訊息去查帳號而問題在網路;而且要等 **21 秒**(作業系統重送 SYN)。改:`LoginResult.Unreachable`+登入前先探 TCP 埠(1.5 秒,**不用 ICMP ping,醫院常擋**)+訊息改「無法連線到伺服器主機(位址)」+不清空密碼欄。**同時移除直連資料庫的登入路徑**(`SystemConfig.CheckUserPassword`,`DownloadHost` 是 localhost 時原本會客戶端自己比對 BCrypt)——驗證帳密是伺服器的職責。**⇒ `DownloadHost` 現在是必填**,登入一律走 WebApi。

**測強制模式**:DEBUG 組建吃 `HD_LICENSE_ENFORCE=1`(Release 不吃),免得每次改常數又忘了改回來。

**端到端實測(對 .191)**:申請 257ms 寫入 → 第二次啟動**不會重複開一台** → 主控台簽發 → 看片端自己取回落地判定 Valid → 之後每次 30ms 且不碰 DB → 餵一份別把金鑰簽的授權回 `BadSignature`。另有簽發服務 15 項測試。

**⚠️ 簽發在封閉網路下還沒解(backlog REQ-015,2026-08-14 裝機前才確認)**:`.191` 主控台**連不到醫院 DB**、醫院主機**不對外連不到 sso.ltcd.tw**(大部分醫院都是封閉網路,資安要求),**只有工程師筆電同時碰得到兩邊**。**連帶推翻「醫院端也裝一份唯讀主控台」的既有規劃**——它的登入是 OIDC 導 Keycloak,封閉網路走不到登入頁,要另給本機帳號。三個選項:①主控台跑筆電(最快但私鑰要複製到個人機器,此性質先前已否決)②**拉/簽/推**(筆電小工具讀醫院 DB 待簽發→在 .191 簽→寫回醫院 DB;私鑰始終在 .191 不綁人)③純手工(測試時的做法,十台內可行)。**三個動作都不碰醫師的電腦**。不急著決定:蒐集階段不擋人,等清冊長出來看實際幾台再定。
